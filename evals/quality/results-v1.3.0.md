# v1.3.0 评估记录

## 简历质量盲评

冻结 v1.2.0 `c6e1de9` 与 v1.3.0 首轮质量快照 `5eb1b48`。三份合成案例覆盖综合职能、内容运营和人力项目支持。两版收到同一份 JD、同一组候选人事实和同一条出稿要求。各运行三个独立的临时 Codex 会话，每个会话生成三例。同用 gpt-6.1-sol、低推理强度。基线运行器带有 `--ignore-rules`，正式候选和公开运行器移除了该选项。两组均在只读临时目录生成，提示均禁止使用工具。这是两组运行配置的已知差异。

18 份稿件按案例与轮次组成 9 对。各对顺序和 A/B 位置独立打乱。单独的模型评审收到匿名稿件、题面和固定量表，未获得组别映射。每份先在四维度独立打分，再选偏好。评分写入后，按留存的内容哈希核对并揭晓版本。

**v1.3.0 得到 4 胜、4 平、1 负。** 综合职能三轮均选新版，内容运营两平一负，人力项目支持一胜两平。结果只覆盖这三份合成案例与一名模型评审。

新版在首屏信息顺序和措辞上得分更高，岗位相关性略低。人力项目支持有两份稿件为精简遗漏了任务负责人、截止日期和状态维护的具体证据。内容运营有一份稿件把「按规则剔除无效答卷」扩成了未确认的「逐份检查」。发现后补了两条规则。精简前先核对 JD 每项任务的唯一证据，改写动作时保留原始证据的具体程度。盲评分数仍对应修订前的冻结快照。

## 原 22 条行为用例

保留原用例和必需、禁止项。v1.3.0 核心规则快照用三个独立临时会话各回答 22 条，由独立会话按原量表评分。每轮将案例分开作答，测试提示要求约 90–180 字，复杂场景可略长。跨会话日志题所用的合成库和缺文件分支都实际执行过。这个设置检验短答时的规则完整性。

| 轮次 | 必需项齐全且无禁止项 | 无禁止项 |
| --- | ---: | ---: |
| 第 1 轮 | 8/22 | 22/22 |
| 第 2 轮 | 6/22 | 21/22 |
| 第 3 轮 | 6/22 | 22/22 |
| 合计 | 20/66 | 65/66 |

4 条用例三轮均满足全部判据。多数缺项是少给一项核对动作或解释，例如未明确说本次离线、漏列签约确认项、给出了顺序但没排本周档位。唯一触发的禁止项出现在第 2 轮第 15 题，同题复练给出了两个主要改进点。该轮没有触发代投、编造经历或泄露敏感信息类禁止项。随后明确了密码提醒、冲突待核时暂停提交，以及复练须各引用首答与复答并只给一个动作。旧版 22/22 是早先单轮自评分，不能与本次独立短答压力测试直接比较。

## 修订后的定点复查

用当前规则另开三个临时会话，每轮回答四条原行为用例和两个简历案例。不额外限制字数。下表只按列出的观察点复核，由维护者逐项读稿。分数不回填到九对盲评或原 66 次压力测试。

| 观察点 | 满足 |
| --- | ---: |
| 代投请求明确由本人提交，提醒别发密码并给出官方改密动作 | 3/3 |
| 截止冲突列出两处时间，较早日期用于备料，核清前暂停提交 | 3/3 |
| 同题复练引用首答与复答，末尾只给一个可独立执行的改进点 | 2/3 |
| 优先排近截止和滚动岗，分开待核与硬门槛不符 | 3/3 |
| 内容运营简历保留原有问卷清理动作，未增加逐份核查 | 3/3 |
| 人力项目支持简历保留共享表的负责人、截止与状态证据 | 2/3 |

复练的一轮仍在主要动作之外加了公司事实核对提示。项目支持的一轮仍遗漏了进度表证据。结构化投递包脚本因此增加了可执行检查：已匹配的职责若没有关联事实被简历引用，就会在复核区提醒。对应单测验证了提示确实出现。
