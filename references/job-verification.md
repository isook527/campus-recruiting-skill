# 岗位核验

## 找入口和证据

1. 先记录毕业年月、境内外、全职/实习、城市及岗位族。搜索使用「届次 + 当前月份 + 公司或城市 + 方向」，同时覆盖秋招补录、滚动招聘和正式校园招聘。以毕业窗口校验应届资格，届次相同也可能有不同毕业日期、学历或专业要求。
2. 优先招聘方域名、招聘方官网直接链接的 ATS、政府或事业单位正式公告。高校就业网、招聘平台、社交媒体和用户旧表可用来发现线索。承办方网站仅在招聘方公告明确链接或授权的范围内使用。公共报名链接优先，去除可识别为推荐码、会话或个人跟踪信息的参数，保留决定岗位的公开参数。
3. 阅读正文、发布日期、补充和延期公告，再查看投递页显示的计划、岗位代码、城市和是否可以申请。正式政府招聘若公告指定公开邮箱或现场报名，可核验公告中的渠道、时间和材料。只看到个人登录提示时，先检查公开部分能否证明对应项目和入口。页面受限时记录实际看到的内容，停在公开页面。
4. 核对截止时区和具体时间。公告只写截止日期时保留日期，标明时刻未公布。当天缺时刻要重新确认具体开放状态。截止时间无说明时保留「未公布」，要求当前官方具体岗位出现明确的可投状态或直接可用的申请入口。多个日期冲突时用更新且适用于该岗位的正式公告，冲突未消除就保持待核。
5. 去重用招聘方、岗位 ID、批次、城市。没有岗位 ID 时用标准化的公司、准确标题、城市和批次判断，同名异地或不同子机构保留。保留最新且证据完整的入口。

## 结果分组

| 状态 | 可接受证据 | 处理 |
| --- | --- | --- |
| `verified_open` | 本次同时核对官方公告和对应具体岗位投递页，资格及开放状态可判定 | 放在可投岗位，保留核验时间 |
| `campaign_open` | 本次核对同一招聘项目，公告说明窗口开放，报名页明确显示当前项目在招职位或该项目的有效申请入口 | 放在项目入口，提醒进入后另核具体岗位 |
| `not_started` | 官方的报名开始时间在未来 | 放在待开始，显示时间 |
| `closed` | 官方说明结束、招满或明确截止日已经过去 | 排除出可投区 |
| `unverified` | 仅有转发或历史记录、投递页不可读、身份/日期冲突，或只看到了泛入口 | 另列待核原因 |

搜索结果按城市、资格和类型筛选后，可按截止临近程度、匹配证据、核验时间排序。若只找到一两个合适岗位，保留真实数量。地区或学历未公布时如实留空。用户明确要求更新本地表时，生成新文件并从默认可投结果排除结束、重复、过时和无法验证的记录；把其他状态按需另列。优先保留原始文件，避免把关停和暂时不可读混为一类。

职位介绍页上的「立即投递」有时就是该岗位的网申入口。若当前招聘列表也把同一岗位列为可投，且入口在该岗位页可见，两者可以互证。只看到项目介绍、空白招聘框架、通用登录页，或无法确认按钮对应哪一个职位时，保持待核。区分「按公告尚未截止」和「本次确认网申入口对应且可用」。

## 结构化核验记录

校验器接受一个 JSON 数组，每条对象使用以下字段。没有薪资、城市或学位公告时可用 `null`。不保存招聘页面全文、个人简历、推荐码和登录信息。

| 字段 | 写法 |
| --- | --- |
| `id` | 唯一短 ID，优先关联公开岗位代码 |
| `employer`、`title`、`batch` | 招聘主体、正式岗位/项目名、批次，如「2027届秋招」 |
| `scope`、`employment_type` | `position` 或 `campaign`；`campus`、`internship` 或 `public_hiring` |
| `city`、`eligibility`、`salary` | 城市、明确的硬性资格、公开薪酬（含单位和期间） |
| `announcement_url`、`application_url` | 官方公开 HTTPS 链接；公告和投递同页时可相同。指定公开邮箱或现场报名时，以说明报名渠道的正式公告作为申请证据页 |
| `checked_at` | 本次核验时刻，ISO 8601，包含时区 |
| `opens_at`、`deadline` | 有时刻的用带时区时间戳；只给日期用 YYYY-MM-DD；未知用 `null` |
| `status` | 上表状态 |
| `announcement_evidence`、`application_evidence` | 本次实际观察到的届次/窗口和对应岗位/项目申请状态，写事实摘要 |

运行 `python3 scripts/check_jobs.py 记录.json`。输出的 `eligible_by_record` 是同日、时序和格式均合格的记录，还需与本轮网页观察相互对应。缺少精确截止时刻的记录到截止日自动退出此列表。可通过 `--as-of` 复现历史规则结果，历史运行不能作为当前核验。没有网页证据时，输出零条实时岗位，允许继续使用离线求职资料。

### 来源枚举与时效

新记录增加 `source_type`。用 `employer` 标注招聘方原始来源，`authorized_ats` 标注沿官方链路确认授权的网申系统，`public_authority` 标注主管机构发布的当期公告。仅有转发或聚合信息用 `third_party`，无法判定用 `unknown`。后两种只留线索。旧记录缺此字段时仍按原有证据规则读取，投递前需按当前流程复核。两个同级官方来源冲突且尚未找到明确更正时，保留原文和时间，填写 `official_conflict: true`。

脚本沿用北京时间同日且最长 8 小时的岗位核验窗口。结果的 `deadline_countdown` 对精确截止给秒数，对只有日期的截止给日历日差，未知截止保留未知。倒计时按记录里的时间计算，最终以复核后的官方公告为准。默认退出码为 0（完成校验）或 2（输入错误），传入 `--warn-exit` 时，待核、过时、冲突等警告会输出完整报告并返回 1。
