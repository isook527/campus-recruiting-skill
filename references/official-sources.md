# 官方入口与核验状态

这些入口只用于发现和回溯信息。`last_verified` 表示本次能够打开并确认该入口的用途，不表示其中每个岗位仍开放，也不替代对具体公告、岗位页和投递页的当次核验。

- 日期超过 30 天时，重新打开后再使用。
- `仅导航，不追踪日期` 的入口只作为检索线索，脚本跳过日期检查。这些入口不能单独支撑「可投」「安全」或合同判断。
- 动态页面、登录页或验证码页即使能打开，也只能证明入口存在。岗位状态仍按 [岗位核验](job-verification.md) 处理。

## 使用顺序

1. 从入口发现单位或项目。
2. 打开本轮招聘公告，核对招聘主体、届次、城市、硬门槛、截止时间和变更说明。
3. 打开公告指向的具体岗位页或网申页，核对岗位 ID、投递状态和互斥规则。
4. 若涉及收费、培训、贷款、个人信息或签约，先暂停相关动作，再查对应官方入口和完整文本。
5. 来源冲突时并列记录，不替发布方裁定。按更早截止安排，并通过招聘方官方联系方式补核。

## URL、账号和日期怎么判断

- 链接显示文字可以被任意命名。核验时看实际 URL 的主机名、协议和完整路径，不只看「官网」「校招入口」等标签。
- 主机名拼写相近不等于同一站点。子域名、跳转域名和第三方 ATS 需要由招聘方官方公告或主站明确关联。
- 同一官方主机名下的旧路径、归档页或通用首页也不能证明本轮岗位开放。继续核公告日期、岗位 ID 和投递状态。
- 平台的官方或招聘账号认证是核验线索。五部门通知要求平台分类核验并展示招聘服务账号资质，但认证仍不能替代具体岗位和链接的当次复核。
- 微信公众号先从单位主站的二维码或招聘公告回溯，再核对微信「账号主体」与用人单位或其授权运营方。只看到昵称相同、搜索摘要标「官方」或转发截图时保留为线索。
- 每次更新入口后运行 `python3 scripts/check_sources.py`。脚本检查导航表和参考资料中带核验日期的链接。导航表按 30 天，其他参考资料默认按 90 天，仍需人工打开网页复核。

城市、专业或行业未覆盖时，搜索「单位全称 + 当前届次 + 校园招聘」，再从单位官方主站回溯招聘入口。政府就业专题或高校转发可以扩充线索，不能替代用人单位当期公告。
