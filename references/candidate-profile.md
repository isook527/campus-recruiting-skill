# 一份档案，多处复用

先问用户有无已保存的求职档案。用户选定路径后，只从该文件读取本次用得到的字段。新会话可直接说「沿用这份档案，查上海的银行岗」。没有档案也可以做当前任务，只问会改变结论的缺口。用户明确要求保存时，再在其选定位置新建或更新。

## 档案卡

| 区块 | 可填写 |
| --- | --- |
| 学历 | 学校、本人确认的院校层次、第一学历和当前或最高学历、专业、毕业年月、GPA 原始口径及排名 |
| 资格 | 英语、证书。政治面貌和生源地在目标岗位明确相关时由本人自愿补充 |
| 偏好 | 意向城市、目标方向、每周可投入小时数 |
| 经历 | 已确认的事实卡编号。可关联同一私有目录里的脱敏事实卡文件 |

把第一学历写成用户确认的教育经历口径，例如「统招本科」。不要自行从学校名称推断院校层次，也不要把第一学历、GPA 或政治面貌当作所有岗位的筛选规则。判断资格仍逐字对照当期公告，保留原始要求与例外。GPA 与排名保留原分制和分母，例如「3.6/4.0」「12/108」，缺失就留空。

当前对话中用户明确修正的事实优先。发现矛盾时只问相关字段，确认后再更新档案文件。候选人事实和目标岗位要求各自记录，未填字段不能视为不满足。

## 各模块读什么

| 场景 | 复用档案字段 | 现场补什么 |
| --- | --- | --- |
| 资格核验 | 学历、毕业年月、英语或证书 | 当期公告和会改变资格的缺口 |
| 投递排序 | 城市、方向、每周可投入时间 | 截止、限报和本周成本 |
| 简历与网申 | 学历及相关事实卡编号 | 本岗前三项任务、字段限制和产出证据 |
| 面试练习 | 事实卡和已确认的故事 | 轮次、题型及上轮真实反馈 |
| Offer | 城市、方向和时间约束 | 书面条件及本人当下优先级 |

## 本地使用

```bash
python3 scripts/candidate_profile.py 私人档案.local.json init
python3 scripts/candidate_profile.py 私人档案.local.json show --section preferences
```

在用户选定的私人目录中运行，或把文件名替换为该目录下的绝对路径。生成后可用文本编辑器填写 JSON。未知值保留 `null` 或空数组。脚本会拒绝覆盖现有档案，读取会校验结构和疑似证件号或手机号。为匹配已知经历，在 `experience_ids` 里填 `F1` 等稳定编号。可选 `fact_cards_file` 填档案目录内的相对文件名，例如 `事实卡.local.json`。Agent 只在用户选定档案后按需读取实际仍位于该目录内的文件，越界路径或缺失文件保留待核。

档案、事实卡和投递库留在私人目录。只向当前任务提供所需字段，勿复制整份档案到聊天输出、公开仓库、云端网申附件或示例。无需填身份证号、手机号、地址、账号、验证码或未脱敏证明。已有普通笔记也可按同一字段使用，文件与格式由本人决定。
