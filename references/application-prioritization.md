# 投递优先级

## 先过资格和渠道关

| 结论 | 条件 | 下一步 |
| --- | --- | --- |
| 可排期 | 具体岗位和网申有效，硬门槛逐项满足，已核对志愿规则 | 排期并在提交前复核 |
| 条件成立才投 | 任一硬门槛、官方入口、有效期或志愿约束待核 | 写清「若 X 且 Y → 投，否则 → 不投」，标明向谁确认，期间只备料 |
| 跳过 | 官方明确关闭，或有依据证明硬门槛不满足 | 停止这岗的定制，按真实资格找替代岗位 |

每条硬门槛标「满足 / 不满足 / 待核」。核对毕业年月、境内外窗口、往届例外、学历、专业目录、政治面貌、生源地、户籍、证书和工作许可，按当期原文保留「且 / 或 / 优先」。例如「限本省生源或本省高校毕业生」，确认第二项满足时，这条满足，其他条件仍须逐项核验。

## 用四个因素排同档岗位

1. **匹配度**。把岗位前三项任务与本人证据对齐。直接做过优先，可迁移经历其次。城市、用工条件、到岗时间按本人偏好筛。
2. **信息可信度**。同一批次的原始公告和具体网申状态一起核验。仅有转发或官方冲突时排进核对清单。保留两份冲突时间，按较早时间备料并核实。
3. **剩余时间**。先安排约三天内截止且能完成的岗位，再提前安排公告明确滚动录用的岗位。只有日期写剩余日历日，没公告写未公布。剩余时间相近时用匹配证据和成本破同档。
4. **机会成本**。估算定制、材料、测评和路途耗时。提交会消耗同一单位的名额或让别的志愿锁定时，先比较首选和备选。在精力有限时优先做证据更匹配、时间够、投入可控的岗位。

限报一个岗时只给待用户确认的一项选择，其他作为备选。允许多个志愿时，核对先后顺序、第一志愿是否锁定、后续是否自动调剂、提交后能否修改，以及已投岗位是否占名额。若公告的口径有歧义，向官网公布的招聘渠道核实后再操作。把同一单位的相关岗位一起展示，用户确认选择和顺序。滚动岗位只有官方明确写明才标注。

## 本周怎么排

- **对口**。主要任务有直接证据，先排本周临近截止和滚动岗，留出定制与测评时间。
- **保底**。资格满足，城市和条件本人愿意接受，已有材料可以快速适配。安排一段固定时间处理，避免高成本冲刺挤掉。
- **冲刺**。资格满足，但任务证据或经验深度有差距。先设准备上限，到点复盘是否继续。

按本人本周可投入的小时数填写时间块。先锁截止与测评，再安排对口、保底和冲刺。没有给预算时先给可调整的例子，比如三个晚间时段分别用于紧急对口、滚动与保底、冲刺和复盘。每条行动写清日期、耗时或预算、解锁条件，记录留给本人操作。三档反映投入策略，录用概率无从推算。
