# 面试故事矩阵

用于把少量真实经历变成可追问、可复练的面试材料。适合同时准备三道以上行为题，或回答总在不同经历之间跳转时使用。矩阵是练习稿，不改变投递包的 facts schema，也不能把待确认内容升级为简历事实。

## 先选故事，不先写答案

从已确认事实或材料中选 6—8 个核心故事，来自课程、实习、社团、兼职或志愿服务。同一段经历可以拆成两个不同事件。证据只够三四个时先保存现有故事，剩余能力留为待补。一个故事必须有本人动作，以及可复述的结果或边界；能指向产物或记录时一并写入。只有团队结果、能力形容词或想象方案时先不入库。

| 故事及事实卡 | 本人动作和取舍 | 产物、结果及边界 | 能力与可回答题目 |
| --- | --- | --- | --- |
| S1 · F2/F3 | 当时任务、限制、本人两步行动及选择依据 | 实际交付及核对方式。未记录的数字保留未知 | 选 1—3 项强能力，列出能回答的题号或题干 |

## 能力与题目怎么映射

| 能力 | 必须能讲清 | 可挂的题目 |
| --- | --- | --- |
| 领导与协作 | 如何让多人形成共识或交付，本人权限是什么 | 如何推动队友配合、如何分工 |
| 冲突 | 两方分歧、你的具体处理及共同结果 | 如何处理不同意见、如何给难反馈 |
| 失败与复盘 | 目标如何没达到、你承担什么、复做改哪步 | 最大一次失误、方案被拒后怎么办 |
| 抗压与优先级 | 突发限制、取舍、沟通风险和质量底线 | 多任务同截止、临时变更如何处理 |
| 主动 | 原先没人要求的缺口、你采取的动作和可核结果 | 如何发现问题、如何推动流程改进 |
| 学习 | 如何补能力、如何用在真实任务上、怎样验证 | 上手陌生任务、用反馈修改方案 |
| 细致与合规 | 核对标准、异常处置、留痕和权限边界 | 如何避免错漏、如何纠正台账差异 |
| 服务 | 对象需求、处理预期和后续验证 | 怎么处理投诉、需求不明确怎么办 |

一个故事可以挂多个问题。比如已确认的材料汇总故事可用于「如何协调多人」「怎么避免遗漏」「材料迟到如何取舍」。每题更换开场和突出动作，事实和归属保持一致。某种能力说不出对应动作时，这个故事不用于该题。

## 开放式补全

依次问，不预设用户成功、主导或产生了增长：

1. 事情开始时，原始任务、限制和截止是什么？
2. 团队里你实际负责哪一部分，哪些不归你决定？
3. 当时至少有哪两个做法，你为什么选了其中一个？
4. 你按什么顺序做了哪些动作；遇到异常时找了谁？
5. 最后交出了什么；可以用什么材料或反馈核对？
6. 哪些数字、效果或归因没有记录，必须留在边界外？
7. 如果重做，只改哪一个动作，为什么？

回答中新增的金额、人数、时长、任期、工具和职责先标「待补」。用户确认或材料支持后再更新矩阵；不能因为面试答案更顺而自动写回简历。

## 压成 60 秒与 120 秒

先写 60 秒骨架：

```markdown
背景与任务：一句，说明限制和本人任务
关键动作：两步，其中一步写选择理由
结果与边界：产物或可核对结果；一句未知项
岗位连接：这套方法怎样对应当前 JD 的一个动作
```

120 秒版只增加一个真实卡点、一个判断过程和一条复盘，不增加未经确认的数字。讲完后让听者复述「本人做了什么、依据是什么、结果如何核对」；复述不出来就缩短背景，保留动作与证据。

## 覆盖检查与练习

1. 从当前 JD 圈出三项动作，不从岗位名称猜能力。
2. 每项动作各选一个最强故事；同一故事可以复用，但追问角度要不同。
3. 对「冲突或失败」「准确性」「推动他人」「为什么选这个岗位」各检查是否有可用故事。
4. 缺口只补事实或换故事，不编一个更漂亮的案例。
5. 从[分行业与轮次题库](interview-question-bank.md)选一题，用[同一量表](interview-coaching.md)做两轮回答。

输出时只展示本次轮次最相关的 2—3 个故事、覆盖缺口和下一道练习题，不把整张私人经历库放进公开投递材料。
